## 先说明要找什么

二分查找不只用于回答一个值是否存在，也可以寻找第一个不小于目标的元素。本篇使用后一种定义：输入一个按非递减顺序排列的数组，输出最左侧满足条件的位置。如果没有元素满足条件，返回数组长度。这样的定义能自然处理重复值和插入位置。

相比“找到就返回”的写法，这个问题要求我们即使遇到相等元素也继续检查左侧。否则数组里有多个相同值时，结果会依赖某次恰好取到的中点，无法保证最左位置。先写清返回值的含义，代码才能被可靠地测试。

### 左闭右开区间

候选区间记作 `[left, right)`。开始时 left 为 0，right 为数组长度。区间之外已经有结论：left 左侧都小于目标，right 及其右侧都不小于目标。每轮只更新一个边界，直到两个边界相遇。

## 实现与不变量

```cpp
#include <vector>
#include <cstddef>
std::size_t lowerBound(const std::vector<int>& values, int target) {
    std::size_t left = 0, right = values.size();
    while (left < right) {
        const auto mid = left + (right - left) / 2;
        if (values[mid] < target) left = mid + 1;
        else right = mid;
    }
    return left;
}
```

### 为什么右边界不减一

当中点满足“不小于目标”时，它仍然可能是答案。将 right 设为 mid，代表这个位置已经属于已知的右侧区域，而最终边界仍有机会停在那里。左边界更新则必须越过中点，因为中点已经确定小于目标，不可能再是答案。

这套解释依赖左闭右开的约定。换成两端都包含的区间时，循环条件和更新方式也应一起调整。不能只抄其中一个 `+1` 或 `-1`，然后靠多跑几组样例猜测是否正确。

## 含重复值的过程

数组为 `[1, 3, 3, 3, 8]`，目标为 3。第一次中点落在下标 2，满足条件，于是 right 变为 2；下一次中点为 1，再次满足条件，right 变为 1；最后检查下标 0，小于目标，left 变为 1。区间闭合，结果为 1。

| 输入 | 目标 | 结果 | 含义 |
| --- | --- | --- | --- |
| 空数组 | 3 | 0 | 插入到开头 |
| `[3]` | 3 | 0 | 第一个元素满足 |
| `[1, 3, 3, 8]` | 3 | 1 | 最左重复值 |
| `[1, 3, 8]` | 9 | 3 | 没有元素满足 |

### 确认值是否存在

返回位置不等于保证找到了目标。如果位置等于数组长度，就不能访问数组；否则仍要比较该元素是否等于目标。例如查找 2 会返回值为 3 的位置，它是正确的边界，但不是一个相等元素。

## 不只依靠几个样例

可以用线性扫描写一个简单的参考实现：从头找到第一个满足条件的元素，再与二分结果比较。对许多短数组、重复值和边界目标进行比较，能够帮助发现遗漏。参考实现应该足够朴素，避免与待测实现共享同一种边界错误。

### 复杂度与前提

每轮候选长度约减半，因此随机访问数组上的比较次数为对数级。前提是数组已经有序，并且在查找过程中不被修改。如果输入没有满足前提，返回一个看起来合理的下标也不代表算法正确。使用标准库时，同样要阅读接口对区间与比较规则的要求。

## 留给自己的检查顺序

先写返回值定义，再选区间形式，接着说明两边已经知道什么，最后才写中点计算。调试时先看空数组、单元素和重复值，再看长数组。这一顺序能够把“总是差一位”的错误变成可以逐步解释的问题。
