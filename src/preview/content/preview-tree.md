## 树表达层次

在一棵非空的有根树中，有且仅有一个根。根以外的每个节点有一个父节点。一个节点可以有多个孩子，没有孩子的节点称为叶节点。

这些关系让我们能够表达目录、组织结构和表达式，而不必把所有内容排成一条线。

### 二叉树的“二”限制了什么

二叉树的每个节点至多有两个孩子，并且区分左、右。只有一个孩子时，它是左孩子还是右孩子，仍然影响树的结构。

## 遍历关注访问时机

对于二叉树，深度优先的三种常见遍历只需比较“何时访问根”：

| 遍历 | 顺序 |
| --- | --- |
| 前序 | 根、左子树、右子树 |
| 中序 | 左子树、根、右子树 |
| 后序 | 左子树、右子树、根 |

### 层序遍历为何用队列

层序遍历先访问距离根更近的节点。把根入队，每次取出队首并把它的孩子依次入队，队列自然保留了这一先后次序。

## 定义要保持一致

有的资料把根的深度记为 0，有的把根所在的层记为 1。讨论树高时要先说明计算的是边数还是层数，避免出现“同一棵树差一层”的误会。

## 用一棵小树检查三种顺序

设根为 A，左孩子为 B，右孩子为 C；B 的左右孩子分别是 D、E，C 只有右孩子 F。这棵树足够小，可以手算，又包含了缺少孩子的情况，比一棵完美对称的树更适合检查程序。

```text
        A
       / \
      B   C
     / \   \
    D   E   F
```

前序是 A、B、D、E、C、F；中序是 D、B、E、A、C、F；后序是 D、E、B、F、C、A。层序则是 A、B、C、D、E、F。将输出写在一行以后，再给每个节点标上第一次遇见和最终离开的时刻，就能看清三个深度优先顺序之间的关系。

### 中序并不总是排序

只有满足二叉搜索树的顺序约束时，中序遍历才具有相应的有序性质。一棵普通二叉树可以随意放值，中序仅仅定义访问顺序。把“二叉树”与“二叉搜索树”混用，会让推理在第一步就多出一个没有给定的前提。

## 层序遍历的队列变化

根先入队；取出 A 后加入 B、C；取出 B 后加入 D、E；取出 C 后加入 F。队列中可能同时包含当前层剩余节点和下一层节点，但顺序不会混乱，因为下一层总在当前层后面入队。

```cpp
#include <queue>
#include <vector>
struct Node { int value; Node* left; Node* right; };
std::vector<int> levelOrder(Node* root) {
    std::vector<int> result;
    if (!root) return result;
    std::queue<Node*> pending;
    pending.push(root);
    while (!pending.empty()) {
        Node* node = pending.front();
        pending.pop();
        result.push_back(node->value);
        if (node->left) pending.push(node->left);
        if (node->right) pending.push(node->right);
    }
    return result;
}
```

### 空树不是异常树

这里明确允许根指针为空，返回空结果。接口允许哪些输入应该写清楚，不要把空树、只有根的树和含有缺失孩子的树都交给一个含糊的“正常输入”概念。上述代码还假定结构没有环、节点在遍历期间有效，不负责节点的分配与释放。

## 从遍历走向表达式

表达式树中的内部节点可以存运算符，叶节点存操作数。后序遍历适合先求孩子的值，再合并当前节点。不过如果要输出带括号的中缀表达式，仅仅打印中序序列会丢失结构，仍需根据子树边界添加括号。

例如 `(a + b) * c` 与 `a + b * c` 的中序字符可能非常接近，但树根不同，计算过程也不同。可见遍历顺序是观察树的一种方式，不一定单独保留树的全部信息。

### 一份小结

确认结构定义，再检查空树和单节点；选一棵不对称的小树手算；最后分析极端的链状结构。这个顺序比从几十个节点的随机树开始调试更容易定位问题。每增加一个功能，都应说明它依赖的是一般二叉树，还是带额外约束的搜索树。
