## 递归不是单纯地重复自己

一个可结束的递归过程，需要有边界条件，还需要让递归调用逐步接近边界。例如计算阶乘时，每次把参数从 n 减到 n−1，最终到达 0。

```cpp
unsigned long long factorial(unsigned int n) {
    if (n == 0) return 1;
    return n * factorial(n - 1);
}
```

这段代码只适合很小的 n：整数会溢出，递归层数也受调用栈空间限制。数学公式成立，并不意味着有限位宽的程序能处理所有输入。

### 一层调用保存一份状态

调用者需要记住参数、局部状态和返回位置。调用新的函数时，旧的一层暂时等待；内层返回后，外层继续完成自己的工作。

对于 `factorial(3)`，外层等待的是 `factorial(2)` 的结果；拿到结果后还要乘以 3。等待关系呈现了后进先出的次序。

## 什么时候不必使用递归

阶乘可以用循环计算。对这个问题来说，循环消除了逐层调用的额外空间。对于树的遍历，递归却经常能直接对应“处理根节点，再处理子树”的结构。

### 用问题结构选择工具

判断依据应当是代码是否清晰、输入规模和空间限制，而不是递归看起来是否简短。

## 手动模拟返回阶段

理解递归时，不能只画向下调用的箭头。以阶乘为例，调用进入最深一层并不是工作结束，而是结果开始逐层返回的时刻。`factorial(0)` 返回 1，上一层拿到 1 才能计算自己的乘法，之后再把新结果交给更外一层。

| 当前层 | 正在等待 | 收到的值 | 返回的值 |
| --- | --- | --- | --- |
| n = 0 | 无 | 无 | 1 |
| n = 1 | factorial(0) | 1 | 1 |
| n = 2 | factorial(1) | 1 | 2 |
| n = 3 | factorial(2) | 2 | 6 |

### 返回地址也是状态

两层函数即使执行同一段源码，也有各自的参数和继续位置。调试器里的调用栈正是在展示这些尚未结束的调用。阅读时可以把每一层写在一张纸上：参数是什么，已经完成什么，还缺哪个结果。这样比把整个过程想成函数“跳来跳去”更容易检查。

## 从二分查找观察区间收缩

递归的终止性可以由一个严格减小且有下界的量说明。例如使用左闭右开区间时，区间长度是 `right - left`。每次递归必须让这个长度减小；如果边界更新后长度不变，程序就可能永远调用下去。

### 别只写一个终止条件

有终止条件不代表一定到达。假设中间位置计算为左端点，而递归仍传入原左端点与原右端点，那么终止分支永远不会被命中。检查小区间尤其有效：长度为 0、1、2 的情况，常常比随机的大数组更能暴露边界错误。

## 显式栈与递归栈

递归可以改写为自己维护的栈，但并不是简单地把节点放进去就完成了。前序遍历只需要记录待访问节点；后序遍历还需要知道某个节点的孩子是否已经处理完，否则无法区分“刚来到这里”和“准备离开这里”。

```text
帧 = 当前节点 + 当前阶段
阶段 0：准备访问左子树
阶段 1：准备访问右子树
阶段 2：两个子树已完成，处理节点并弹出
```

### 为什么要保存阶段

调用栈隐式保存了程序继续执行的位置。改成手写栈以后，这部分信息不会自动存在，需要用标记、枚举或者栈中顺序表达出来。比较两种写法时，要比较完整状态，而不是只比较代码行数。

## 深度与总工作量

一棵平衡二叉树的递归深度可以很小，但仍需要访问所有节点；一条退化成链的树则可能同时具有很大的节点数与调用深度。因此时间复杂度和辅助空间应该分别分析。递归函数被调用多少次，与任一时刻同时悬挂多少层，不是同一个问题。

复习时我会写下两个数字：总共创建过多少次调用，最深时保留多少次调用。前者帮助估算工作量，后者帮助判断栈空间。遇到可能退化的输入，不应只根据平衡情况做容量判断。
