## 队列关心到达顺序

队列遵循先进先出，FIFO。和栈不同，它在队尾插入、从队首删除。排队处理请求时，先到的对象通常应该先被处理。

直接在数组开头删除元素并搬移后续内容会带来额外开销。我们可以只移动队首下标，让“逻辑上的队首”不再固定在数组的第一个位置。

### 为什么绕回开头

队尾走到数组末尾时，前面可能已经因为出队而空出了位置。循环下标让这些位置可以重新使用。

```cpp
next = (current + 1) % capacity;
```

这里要求 `capacity > 0`。这个公式表达的是逻辑循环，而不是数组内存真的首尾相接。

## 一套必须说清楚的约定

本文采用：`front` 指向下一个出队元素，`rear` 指向下一次写入位置，并保留一个空槽。

| 状态 | 条件 |
| --- | --- |
| 空队列 | `front == rear` |
| 满队列 | `(rear + 1) % capacity == front` |
| 元素个数 | `(rear - front + capacity) % capacity` |

数组容量为 5 时最多保存 4 个元素。少用一个槽，是为了仅靠两个下标区分空和满；也可以另外保存元素个数，从而使用全部空间，但那是另一套约定。

### 不要混用不同实现的判定式

如果某份代码把 `rear` 定义为最后一个元素，而不是下一次写入位置，上表就不能照搬。读代码之前先画出下标指向，比背诵公式更可靠。

## 手动走一遍

设容量为 5，`front = 3`，`rear = 1`。有效元素依次位于 3、4、0，共三个。新的元素写入位置 1，随后 `rear` 更新为 2。

队列的逻辑顺序是从 `front` 开始沿着循环方向读取，不是从数组下标 0 开始读取。

## 一次跨越数组末尾的完整过程

设数组容量为 5，初始两个下标都为 0。先插入 A、B、C，此时队首为 0，队尾为 3。取出 A 和 B 后，队首变为 2；再插入 D 和 E，队尾先到 4，再绕回 0。数组物理开头重新可用，但队列的逻辑开头仍然是下标 2 的 C。

此时元素顺序是 C、D、E。若再插入 F，写入下标 0，队尾到 1。下一次写入会使队尾追上队首，因此需要拒绝。不能看见数组里残留的 A、B 就认为它们仍在队列中，是否有效取决于下标约定，而不是旧内存有没有被擦掉。

### 残留数据不等于有效元素

对整数等简单元素，出队后不清零通常不会影响逻辑结果；对持有资源的对象，则还要考虑对象何时析构。教学用下标模型不自动等于适合任意类型的完整容器，尤其不能忽略对象生命周期和异常处理。

## 一个固定容量的整数实现

下面保留一个空槽，并在接口中显式返回成功与否。读队首使用 `optional` 区分“没有元素”和“元素的值恰好是零”。这个示例需要 C++17。

```cpp
#include <array>
#include <optional>
#include <cstddef>

class RingQueue {
    static constexpr std::size_t capacity = 5;
    std::array<int, capacity> data{};
    std::size_t front = 0;
    std::size_t rear = 0;
public:
    bool push(int value) {
        const auto next = (rear + 1) % capacity;
        if (next == front) return false;
        data[rear] = value;
        rear = next;
        return true;
    }
    std::optional<int> pop() {
        if (front == rear) return std::nullopt;
        const int value = data[front];
        front = (front + 1) % capacity;
        return value;
    }
};
```

### 为什么不在出队时整体搬移

整体搬移会让一次出队与剩余元素个数相关；这里只更新一个下标，固定容量模型下的入队、出队为常数时间。代价是逻辑顺序与物理顺序不再一致，因此遍历和调试都必须从队首开始，而不能直接打印整个数组冒充队列内容。

## 测试绕回，而不只是测试装满

只做“连续插入直到满”不足以验证循环队列。最关键的场景是插入一部分、取出一部分、再次插入，让两个下标都跨越数组末尾。每次操作后记录队列中应有的元素序列，再和程序输出逐项比较。

测试还应确认失败操作不改变状态：队列满时插入失败，已有元素必须保持顺序；队列空时弹出失败，下标也不能继续向前走。错误分支往往比正常分支更容易藏着数据丢失问题。

### 扩展到并发之前

这个实现只有单线程语义。不能因为每次只更新一个下标，就把它直接用于多个线程。并发队列还需要同步、内存顺序以及生产者和消费者数量等约束。先把单线程的不变量验证清楚，再讨论并发，能够少混淆一层问题。
