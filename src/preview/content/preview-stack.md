## 从受限的操作开始

栈是一种只在一端插入和删除的线性结构。这一端叫作栈顶。把元素放进去叫 `push`，把栈顶取出来叫 `pop`。这里最重要的不是它长什么样，而是操作受到了什么限制。

如果依次放入 A、B、C，再连续取出，得到的顺序就是 C、B、A：后进先出，LIFO。

### 顺序不是随意颠倒

实际程序可以交替执行入栈和出栈。因此，按 A、B、C 的次序入栈，并不意味着所有合法输出都必须是 C、B、A。例如先放入 A 就取出，再放 B、C，能得到 A、C、B。

但是 C、A、B 不可能：要先取出 C，A 和 B 必须已经在栈内；此时挡在 A 上面的 B 必须先出栈。

## 用括号匹配观察栈

遇到左括号就入栈；遇到右括号，检查它是否与当前栈顶配对。最后，栈必须为空。这同时检查了嵌套顺序和数量，而不仅仅是左右括号各有几个。

```cpp
#include <stack>
#include <string_view>

bool balanced(std::string_view text) {
    std::stack<char> pending;
    for (char c : text) {
        if (c == '(' || c == '[' || c == '{') {
            pending.push(c);
        } else if (c == ')' || c == ']' || c == '}') {
            if (pending.empty()) return false;
            char top = pending.top();
            bool matches = (top == '(' && c == ')')
                        || (top == '[' && c == ']')
                        || (top == '{' && c == '}');
            if (!matches) return false;
            pending.pop();
        }
    }
    return pending.empty();
}
```

### 空栈必须先判断

`top()` 和 `pop()` 都要求栈非空。不能先读取栈顶，再检查有没有元素。程序中的这一步顺序，正对应了数据结构的使用前提。

| 输入 | 结果 | 原因 |
| --- | --- | --- |
| `([])` | 匹配 | 后打开的括号先关闭 |
| `([)]` | 不匹配 | 嵌套次序交叉 |
| `(` | 不匹配 | 扫描结束后栈不为空 |

## 时间与空间

每个字符只检查一次，每个左括号最多入栈、出栈各一次，因此时间复杂度为 O(n)。最坏情况下，全部字符都是左括号，辅助空间为 O(n)。

> 栈保存的是“尚未完成、且有嵌套关系”的工作。

## 复习时的三个问题

1. 当前栈顶代表哪个尚未处理完的对象？
2. 为什么必须优先处理它，而不是栈底对象？
3. 空栈与非空栈分别意味着什么？

## 把一次扫描展开成状态表

只读代码容易忽略状态变化。用输入 `a + (b * [c - d])` 逐字符扫描时，普通字母和运算符不会改变栈。读到左圆括号时，栈中出现一个尚待完成的任务；读到左方括号时，新的任务覆盖在旧任务之上。右方括号只能结束最近的方括号任务，不能越过它去寻找更早的圆括号。

| 当前字符 | 操作前的栈（底 → 顶） | 操作 | 操作后 |
| --- | --- | --- | --- |
| `(` | 空 | 入栈 | `(` |
| `[` | `(` | 入栈 | `( [` |
| `]` | `( [` | 检查并弹出 | `(` |
| `)` | `(` | 检查并弹出 | 空 |

### 三种失败不能混在一起

第一种失败发生在栈为空却读到右括号，说明没有对应的开始。第二种发生在栈顶类型不匹配，说明嵌套顺序被破坏。第三种发生在扫描已经结束、栈却不为空，说明有任务开始了但没有结束。它们都返回失败，却可以给用户不同的错误信息。

如果要报告错误位置，栈里可以保存括号及其下标，而不只是字符。这样遇到不匹配时既能指出当前右括号，也能指出它原本对应的左括号。不过这仍是简化的语法检查：字符串字面量里的括号、转义字符以及注释，都需要词法层面的处理。

## 撤销功能中的两只栈

编辑器的撤销与重做常用两个栈解释。执行新操作时，把它压入撤销栈，并清空重做栈；撤销时将操作从撤销栈转移到重做栈；重做时反向移动。之所以要清空重做栈，是因为撤销之后的新操作已经走向了另一条历史分支。

### 操作记录与完整快照

保存整份文本比较直观，却可能耗费大量内存。只保存“在某位置插入某段文本”这样的操作记录更紧凑，但需要正确实现逆操作。实践中还要考虑一次中文输入、多字符粘贴和连续退格应当如何合并成用户理解的一步。

这里的数据结构只提供后进先出的顺序，并不会替应用决定“一次操作”是什么。设计接口时，先确定用户想撤回的单位，再选择记录方式，比先写两个栈再补语义更稳妥。

## 用反例验证实现

可以准备空字符串、只有普通字符、全部左括号、全部右括号、合法嵌套、交叉嵌套六组输入。空字符串在当前定义下合法，因为不存在未完成的括号任务；这是一项约定，不能仅凭直觉认为输入为空就应报错。

```cpp
#include <cassert>
// balanced 的实现见上文。
void test_balanced() {
    assert(balanced(""));
    assert(balanced("plain text"));
    assert(balanced("{[()]}"));
    assert(!balanced("([)]"));
    assert(!balanced("((("));
    assert(!balanced(")"));
}
```
