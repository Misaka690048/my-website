---

有时，学习并不是从一个完整的计划开始的。它可能来自一个报错、一段没有读懂的话，或者某个反复出现的小问题。把这些片段写下来，是为了让它们在下一次遇到时，不再完全陌生。

这篇样张用来感受长文的阅读节奏。你可以展开右侧的目录，跳到任意章节，也可以慢慢向下读，看看文字、引用和代码之间是否留出了合适的空间。

## 从一个具体问题开始

“我想学会做网站”是一个方向，却不太容易直接动手。把它换成“为什么我改了文件，网页却没有变化”，下一步就清楚了许多：确认文件保存，确认服务正在运行，再确认浏览器访问的是哪一个地址。

好的问题通常带着上下文。记录自己做了什么、期待出现什么、实际看到了什么，比只记下“没有成功”更有帮助。过几天重新打开这篇笔记时，这些细节能够把当时的思路找回来。

> 不必急着给问题起一个很大的名字。先把眼前这件事说清楚。

### 留下当时的观察

可以保留完整的错误信息，也可以写一小段自己的描述。前者方便定位，后者能解释这个问题为什么值得解决。如果有图片，最好说明它展示了哪个步骤，而不是只放一张没有上下文的截图。

还没有弄清楚的部分也可以写下来。笔记不必在保存的那一刻就成为答案；它首先是一次思考的记录。

## 一次只改变一件事

同时修改很多地方，有时确实能让问题消失，却很难知道究竟是哪一步起了作用。下一次出现类似情况，仍然可能无从下手。

可以把每次尝试看成一个小实验：先写下猜测，做一个可以撤销的改动，再观察结果。如果结果和猜测不同，就把差异记下来。这比只收集最终成功的命令更容易积累经验。

1. 确认当前状态，留下可以比较的起点。
2. 说明这次准备改变什么，以及为什么。
3. 记录实际结果，包括没有解决的问题。
4. 决定保留修改，还是回到上一步继续尝试。

### 区分事实与猜测

“浏览器显示了新标题”是观察到的事实。“缓存已经全部失效”则可能只是解释。把两者分开，会让笔记更诚实，也给以后的修正留下空间。

一个暂时解释不通的结果，不等于这次尝试没有价值。它至少帮助我们排除了某种可能，或者发现了之前忽略的条件。

## 给代码留下上下文

代码片段应该能回答一个具体问题。下面这段示例把笔记按日期排列，让最近写下的内容出现在前面。阅读时，说明文字和代码应当自然衔接，而不是突然切换成另一种视觉风格。

```ts
type Note = {
  title: string;
  date: Date;
};

function newestFirst(notes: Note[]) {
  return [...notes].sort(
    (a, b) => b.date.getTime() - a.date.getTime(),
  );
}
```

行内代码，例如 `notes`、`date` 和 `newestFirst()`，用于指出正在讨论的名称。它们需要容易辨认，但不应比整句话更抢眼。

如果代码很长，先展示与问题直接相关的部分通常更好。代码之外还需要记录运行环境、输入条件和预期结果，让读者知道该怎样判断它是否工作。

## 整理信息，也整理结构

一篇文章的层级可以很简单：标题说明主题，二级标题划分讨论的阶段，三级标题解释其中的细节。并不是每一段文字都需要单独起一个标题。

右侧目录应当帮助读者找到位置。当读者只想回看其中一个步骤时，不必从头翻到尾；当读者连续阅读时，目录也不应该频繁变化、分散注意力。

| 记录内容 | 可以回答的问题 |
| --- | --- |
| 起点 | 当时的环境是什么，已经完成了哪些步骤？ |
| 尝试 | 修改了什么，为什么做这个修改？ |
| 结果 | 看到了什么，是否与预期一致？ |
| 下一步 | 已经确定了什么，还有哪些地方需要继续验证？ |

表格适合比较结构相同的信息。普通叙述则适合解释原因与过程。选择哪一种形式，取决于它能不能让读者更轻松地理解，而不是为了让页面显得丰富。

## 让阅读保持连续

当一行文字太长，眼睛在换行时容易找错位置；当一行太短，句子又会被切得零碎。正文宽度、字号和行距需要一起看，单独调整某一个数值并不能决定是否舒服。

页面之间也是如此。打开文章、返回列表、跳到下一节，都应该让人知道自己到了哪里。轻微的过渡可以帮助衔接，但不需要每一次操作都强调动画本身。

### 浅色与深色

不同的阅读环境需要不同的明暗关系。浅色页面不必带着纸张的黄色，深色页面也不必把背景压到纯黑。更重要的是，正文、辅助文字、分隔线和链接之间保持清楚的层级。

可以在阅读到这里时切换主题，观察正文是否仍然清晰，代码和表格是否一同变化。好的主题切换不会让阅读位置发生跳动。

### 偶尔停下来

并不是每一篇笔记都需要很长。有些问题只要三段话就能解释清楚，有些过程则需要更多例子。保留适当的空白，是为了让段落和思路有所停顿。

真正影响阅读的往往是这些小地方：一处太淡的说明、一段拥挤的列表，或者突然出现的巨大标题。它们值得在实际阅读时慢慢调整。

## 回头看，才知道留下了什么

隔一段时间再读自己的笔记，常常会发现原先没有察觉的跳跃：某个步骤没有解释，某个结论缺少依据，或者一句“当然如此”其实并不当然。

这时不必把旧文字全部推翻。补充新的理解，注明改变的原因，就能让同一篇笔记继续生长。留下记录的价值，并不只在于保存当时的答案，也在于看见自己理解问题的方式如何变化。

写到这里，可以用一句话回顾：这次真正弄清楚了什么？再留一个小问题，作为下一次继续探索的起点。
